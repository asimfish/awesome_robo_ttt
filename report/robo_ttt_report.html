Motivation

为什么机器人需要「测试时」学习

问题：权重在部署那一刻被冻结

大规模预训练的策略（Diffusion Policy / VLA / 端到端驾驶）把知识固化在参数里。部署后遇到分布漂移——新光照、新物体、传感器退化、轮胎磨损——性能骤降，而重新收集数据微调的周期是天级的。

机会：测试样本本身携带分布信息

TTT 的核心抽象（Sun et al., ICML 2020）：每个无标签测试样本都是关于测试分布的信息，用自监督任务把它「榨」出来更新模型。机器人闭环里这类免费信号更多：跟踪误差、预测-实测残差、任务进度。

但代价同样真实

  • 崩溃：长时程在线更新几乎必然退化（RDumb）
  • 延迟：每帧梯度与实时控制预算冲突
  • 安全：在线改权重 = 运行未认证的新模型（ISO 26262 难题），且打开投毒攻击面（DIA）

本报告回答三个问题

  • TTT 在机器人上有哪几种形态，各自的成本-收益？
  • 怎样把 TTT 装进「安全壳」？
  • 2025-2026 的前沿正往哪里收敛？

Conceptual Map

一枚硬币的两面：改权重 vs 不改权重

System-1 · 权重级 TTT（分类①②③④）

用梯度把测试信息写进参数

  • 裸梯度：每帧 1-20 步 SGD（TTT/PAD/Centaur）——直接有效，但权重漂移、验证困难
  • 结构化 TTT 层：快权重更新是前向的一部分（TTT-Layers/RoboTTT）——延迟恒定、更新规则可预先验证
  • 每任务 LoRA：分钟级，只适合段级适应（ARC-TTT）
  • 测试时 RL：伪奖励驱动（TTRL/TT-VLA）——需要 rollout，适合影子模式

System-2 · 免权重 Steering（分类⑤⑥）

用算力改变输出分布，权重冻结

  • 梯度 guidance：去噪中注入可微目标梯度（Diffuser/CTG/DynaGuide）
  • 采样+重排：best-of-N + critic/verifier（IDQL/RoboMonkey/Hydra-MDP）
  • 搜索：进化/CEM/MCTS（Diffusion-ES/TOAD/SAIL）
  • 噪声空间 RL：学噪声选择策略，基座黑盒（DSRL）——唯一会持续学习的免权重路线

两者正交可叠加（Snell 2024 / TTC Survey 的 System-1/2 框架）：同一份测试时算力，花在梯度上还是采样上，是贯穿全部 51 篇的总取舍。

Category 1 · Foundations

基础层给机器人划下的三条红线

成功条件相关性定收益

TTT++ 理论：TTT 收益随自监督任务与主任务的梯度相关性增大而增大。PAD 消融：控制任务逆动力学 > 对比学习 > 旋转预测；导航任务反转。

→ 选错辅助任务，适应梯度只是噪声。

崩溃机理batch=1 是雷区

SAR：BN 统计在小 batch / 混合偏移 / 类不平衡下必崩——车载流式推理三条全踩。RDumb：长时程下 SOTA 持续 TTA 全部退化到不如不适应，只有定期硬重置可靠。

→ 防护四件套：过滤 + 信任域（EATA）+ 软恢复（CoTTA）+ 重置（RDumb）。

攻击面输入能改模型

DIA：测试批次 5% 恶意样本经 BN/梯度通道投毒，良性样本攻击成功率 >92%。TTA 使「输入影响权重」，审计范式失效。

→ 影子模式 + 输入过滤 + 更新/执行通道隔离是车规语境的必选项。

风险与表达力沿谱系单调上升。证据一致指向：冻结感知、只动末端/低维接口。

元训练是隐形前提

MOLe（2018）：不做 meta-training，大网络在线 SGD 无效。Neural-Fly 的 DAIML、Continual-MAML、TTT-E2E 八年间反复验证：训练管线必须为适应做准备。

速度边界（重要反例）

BayesMPC 真车漂移实验：轮胎到摩擦极限时，失稳时间常数快于在线适应收敛——最需要适应的时刻恰是适应最可能迟到的时刻。对策：前馈推断兜底 + 来得及时主动采集信息。

Category 3 · New Wave

范式跃迁：TTT 从部署补丁变成网络层

TTT-Layers（ICML 2025）

隐状态本身是一个小模型，「状态更新」=一步自监督学习。线性复杂度，长上下文超 Mamba。TTT 变成可以预先验证的网络组件。

TTT-E2E（2025）：方法论基石

测试时直接优化任务损失（只更 MLP），训练期用 MAML 式元学习优化「TTT 之后的损失」——训练/部署目标零错配，128K 上下文快 2.7×，延迟恒定。

成本谱系（每次适应的量级）

形态成本适用
TTT 层前向≈0（恒定延迟）帧级闭环

TTRL：一致性可以当奖励

多数投票当伪奖励驱动 GRPO，无标签也能 RL（AIME24 +159%~211%）。风险：多数派错误时自我强化。

Category 4 · Robot & Driving TTT

落地里程碑：真机 30Hz 与驾驶榜首

RoboTTT NVIDIA GEAR

  • TTT 层入 GR00T N1.7 流匹配 VLA
  • 8K 时间步上下文（30Hz 约 5 分钟）推理延迟恒定，RTX 5090 真机闭环
  • DAgger 蒸馏教会快权重「从失败中恢复」：在线自我纠错 +36%

Centaur 驾驶 TTT 先例

  • Cluster Entropy（候选轨迹聚类熵）作无监督目标，只更新 score decoder
  • 单步梯度 + 4 帧缓冲 + 异步并行：navtest 榜首 PDMS 92.1，navsafe 74.14 vs 基线 56.47
  • 不确定性兼职失败检测（73.6%）；仅开环验证

WAM-TTT 北大/Galbot

  • 部署时「看人类玩」：无标注人类视频经视频预测损失写入快权重记忆
  • 元训练用成对人-机数据对齐两个空间
  • 免重定向、免机器人数据、免任务微调，一致超 in-context 基线

同类：TT-VLA · MPA · Post-Training Survey

TT-VLA 用任务进度伪奖励做测试时 RL，并实证「重建得好 ≠ 做得对」；MPA 用 3DGS 反事实仿真做部署前适配 + 推理时择优；综述把 test-time refinement 确立为后训练第四族。

Category 5 · Test-Time Steering

免权重路线：四象限设计空间与延迟账本

四象限（可组合）

  • 梯度 guidance：Diffuser 开山 → CTG（STL 规则可微化）→ DynaGuide（外挂动力学模型）→ SafeDiffuser（CBF 硬约束，保证实为概率性）
  • 采样+重排：IDQL（IQL critic 抗 OOD 高估）→ RoboMonkey（幂律 scaling law，N=8~32 吃掉大部分收益）
  • 搜索：Diffusion-ES（流形内进化变异）→ TOAD（CEM+warm-start，NAVSIM 94.7）
  • 噪声空间 RL：DSRL——基座冻结可回退，在线 RL 增量沉淀进小噪声策略

铁律（TOAD）

verifier 的分布外泛化决定成败：固定词表 scorer 出分布即虚高，拿去搜索反而低于不搜索。对策：扰动轨迹训练 + 限制搜索半径。

New Categories · 8 & 9

失败检测器与「TTT 之前的阶段」

⑧ 失败检测 = 适应的开关

方法要失败数据?信号
Sentinel (CoRL24)否动作块分布一致性 + VLM 进展
FAIL-Detect (RSS25)否成功分布密度 + 共形阈值
SAFE (NeurIPS25)是（跨任务泛化）VLA 内部特征 → 失败似然

共同点：信号来自策略内部，且用共形预测给阈值统计保证。「检测 → 触发 → 验证 → 提交」闭环的零件已齐。熵类信号抓不到「自信地做错」，触发器必须分层。

⑨ TTT 站在 RL 管线之上

  • 为何 on-policy 早期学崩：价值侧 Q 尺度失配（Cal-QL）× 动作侧探索噪声放大（本仓库源头实验）——两个正交机制
  • 探索噪声有最优频谱：Pink Noise（β≈1）优于白噪/OU；gSDE 从生成端平滑；Q-Chunking 靠分块获得时间相关性
  • 导数接口 = 频谱整形器：积分一次 β+2（白→红，Arm C 崩溃），泄漏积分把颜色拉回中间（E3 恢复）——泄漏系数就是噪声颜色旋钮
  • DPPO（我们的微调基座）/ RLPD / WSRL / HIL-SERL / ConRFT 标定了训练期 RL 与测试时 RL 的成本边界
Trends 1/2

九大趋势（上）

① 接口化适应成为主流

适应对象持续缩小：全模型 → BN → 编码器 → decoder → LoRA → 初始噪声 → 单个潜提示 → 快权重层。基座冻结 + 显式小接口承载全部可变性：审计面小、回滚容易、不碰安全认证。

② 可靠性从兜底升级为准入

事后补救（SAR 恢复 / RDumb 重置）→ 事前准入（VANE 提案-验证-提交；拓扑指导的「要不要适应」预测器）。「什么时候该适应」正取代「怎么适应」成为核心问题。

③ verifier 军备竞赛

形态演化：规则模拟（PDM）→ 蒸馏多头（Hydra-MDP）→ VLM（RoboMonkey）→ PRM+方向（RoVer）→ 相对比较（VLA-ATTC）。RoboMonkey 幂律定律给出 N 的边际收益曲线。

④ 算力分配本身成为学习问题

Snell 的 compute-optimal 被机器人接住：ELASTIC 的 meta-MDP 调度、DA-SIP 难度分类器、DIRECT 场景路由。固定超参 TTS 正被自适应调度取代——常时便宜、危时舍得花。

Trends 2/2

九大趋势（下）

⑤ 自监督目标转向任务耦合

「重建输入」退潮：TT-VLA 批评可预测性目标；TTT-VLA 用 state grounding；VANE 用已执行动作的未来视觉后果；TTRL 用伪奖励。机器人的独特资产：闭环里的免费任务耦合信号（跟踪误差/预测残差/任务进度）。

⑥ 人类数据成为测试时转向信号

WAM-TTT「看人类玩」写入快权重；ITPS 系统化人类交互引导；SAIL 成功档案检索。「部署后学习」的数据源从自身经验扩展到旁观人类，跨具身对齐是钥匙。

⑦ 驾驶域两派对垒

改权重（Centaur，榜首但仅开环、认证难）vs 冻结搜索（TOAD，即插即用、工业友好）。感知 TTA 趋于成熟，规划/决策层 TTT 是前沿；反应式闭环 + 权重级 TTT 至今无人占坑。

⑧ 段级「重建世界再训练」

TTT-Parkour（RGB-D 重建地形 → 仿真微调 → 真机，<10 min）、MPA（3DGS 反事实）：高动态不可重试场景的现实 TTT 形态。时间粒度谱系补齐：帧级 → chunk 级（DREAM-Chunk/DCDP）→ 段级 → 任务级。

⑨ 失败检测器成为标配前置件

Sentinel / FAIL-Detect / SAFE：信号来自策略内部、共形预测给阈值保证。「什么时候该适应」独立成子领域，与 Centaur 触发式 TTT、VANE 提案-验证闭环拼成完整流程。

Insights 1/2

核心洞见（上）

洞见 A · 「安全 TTT」的事实标准正在成形

RoboTTT（更新规则=验证过的网络组件）、DSRL（回退 N(0,I) 即恢复 BC）、VANE（影子提案+证据提交）从三个方向收敛到同一设计模式：冻结基座 + 小可变接口 + 验证式提交 + 一键回滚——可作为任何机器人 TTT 系统的设计检查清单。

洞见 B · 三时间尺度分工是正确架构

毫秒级突变→前馈推断（RMA/AD）；秒-分钟级决策困难→采样/搜索/verifier（RoboMonkey/E-TTS/TOAD）；分钟-小时级慢漂移→梯度 TTT 带防护（Centaur/TTT 层）。单一机制包打天下已被 BayesMPC（适应赶不上失稳）与 RDumb（长时程必崩）证伪。

洞见 C · verifier 质量是共同天花板 → 「验证者优先」

TOAD（OOD 崩溃）、TTRL（多数派错误自强化）、Hydra-MDP（蒸总分的信息瓶颈）三条独立证据链指向同一瓶颈。研究布局应先把 verifier 的 OOD 鲁棒性做扎实（扰动训练/解耦设计/ensemble+LCB/相对比较），再谈 steering 与 TTT 的收益。

Insights 2/2

核心洞见（下）

洞见 D · 元训练是 TTT 的隐形前提

八年证据一致（MOLe 2018 → Neural-Fly DAIML → TTT-E2E → WAM-TTT meta-align）：部署时才加 TTT 注定失败。训练管线必须预埋：辅助头联合训练（PAD）、元学习初始化（MAML 式外环优化「TTT 之后的损失」）、或直接用 TTT 层重构骨干。

洞见 E · 分层控制架构是 TTT 的天然安全垫

策略输出高阶量（加速度/速度目标）、底层经典控制器（PID/MPC）跟踪时，上游适应扰动被低层滤波与限幅——结构性限制单步伤害。证据同构：Neural-Fly 只适应末层增益（控制律兜底）、Centaur 的 TTT 在规划头（控制栈兜底）、DSRL 噪声接口（BC 流形兜底）。这是把 TTT 装进安全壳最便宜的一层。

开放问题（论文机会）

  • 反应式闭环 + 权重级 TTT（Centaur 停在非反应式 NAVSIM）
  • 数十万步连续漂移下的适应增益衰减曲线（机器人版 CCC 基准空缺）
  • 控制域 TTT 层的稳定训练配方（TBPTT+二阶梯度）
  • 「scorer 用于搜索时的可靠性」专门基准
  • ISO 26262/SOTIF 语境下 TTT 的形式化安全论证
